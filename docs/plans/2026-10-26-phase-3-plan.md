# Phase 3 (remote server on Cloudflare Workers) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the four MCP tools from a free Cloudflare Worker and start the daily collection on
time via a Worker cron, while the npm package keeps working on the same code.

**Architecture:** History moves from one big `history.json` read to a compact `stats.json` index
plus per-day files, so every request fits in 10 ms of CPU. The cache becomes asynchronous. A
Worker entry (`src/bin/worker.ts` → `src/worker/app.ts`) serves stateless Streamable HTTP MCP at
`/mcp` and, on a schedule, calls GitHub's `workflow_dispatch` for `collect.yml`. Tag pushes deploy
the Worker from GitHub Actions.

**Tech Stack:** TypeScript 6, `@modelcontextprotocol/sdk` 1.32 (`WebStandardStreamableHTTPServerTransport`,
`CfWorkerJsonSchemaValidator`), `@cfworker/json-schema`, zod 4, Vitest, Wrangler 4 (≥ 4.36),
GitHub Actions.

**Spec:** `docs/specs/2026-10-26-phase-3-remote-design.md`

## Global Constraints

- Free plans only: Cloudflare Workers Free, GitHub Actions on a public repo, npm public packages.
- Every Worker request: ≤ 10 ms CPU, ≤ 50 subrequests. CPU budget test: median < 5 ms for a
  synthetic three-year index.
- `src/core` and `src/worker` use no Node APIs; `wrangler.jsonc` has no `nodejs_compat`.
- Worker address `*.workers.dev`; MCP endpoint `/mcp`; stateless transport (`sessionIdGenerator: undefined`).
- Rate limit: 60 MCP requests per minute per `CF-Connecting-IP`; over it HTTP 429 with `Retry-After: 60`.
- Crons (UTC): `30 6 * * *`, `30 8 * * *`, `30 10 * * *`; `fail_on_error` true only for `30 10 * * *`.
- History caching: 6 h freshness, cache keys `stats` and `day:YYYY-MM-DD`.
- Logs: one line per MCP request (method, tool name, duration, outcome); never IPs or tool arguments.
- Versions: collector/history change ships as **0.2.2**; the Worker ships as **0.3.0**.
- Commits use the repo's noreply identity and end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Every commit passes format check,
  lint, typecheck, tests and build. Tests must pass with `TZ=UTC` and `TZ=Europe/Helsinki`.
- The owner does every login, token creation and 2FA step; the implementer never enters credentials.
- Stop after each task so the owner can test it (each task ends with a "Manual check" step).

## Review Focus

- A date listed in `stats.json` whose day file still answers 404 (raw.githubusercontent.com caches
  for minutes, so the index can be ahead of the files): that date counts as not recorded, the
  request does not fail. → Task 4.
- `GET /mcp` or `DELETE /mcp` from a client against the stateless server: a well-formed 4xx from
  the transport, never a 500. → Task 6.
- A request without `CF-Connecting-IP` (local `wrangler dev`, tests): rate-limited under the key
  `unknown`, no crash. → Task 7.
- The cron firing before the owner has stored `GITHUB_DISPATCH_TOKEN`: a clear thrown error, no
  request to GitHub. → Task 8.
- `history.json` unreadable while `stats.json` is present: both are rebuilt from the day files and
  agree. → Task 5.

```ts
load<T>(key: string, freshMs: number, fn: () => Promise<T>): Promise<Loaded<T>> {
  const pending = this.inFlight.get(key);
  if (pending) return pending as Promise<Loaded<T>>;
  const request = this.resolve(key, freshMs, fn).finally(() => this.inFlight.delete(key));
  this.inFlight.set(key, request);
  return request;
}
// resolve(): await this.store.get(key), then the existing fresh / stale / negative / refresh
// branches; refresh() awaits store.get/set.
```
