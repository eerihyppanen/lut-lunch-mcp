# 0.3.2 Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.3.2: ten robustness and hygiene fixes from the 2026-11-14 project review, the
most pressing being a closed Yolo during the Christmas break.

**Architecture:** Small changes in place: the Yolo and Poweresta sources, allergen
normalization, the stats.json decoder, the Worker rate limiter, the remote smoke script, the deploy
workflow, dependencies and docs. No new modules, no format changes.

**Tech Stack:** TypeScript 6, MCP SDK 1.32, zod 4, cheerio, Vitest, Wrangler 4, GitHub Actions.

**Spec:** `docs/specs/2026-11-14-v0.3.2-fixes-design.md`

## Global Constraints

- `stats.json` stays schema 1; files written by 0.3.x collectors must keep decoding.
- No major dependency upgrades (TypeScript 7, @types/node 26 stay out).
- Every commit passes format check, lint, typecheck, tests (UTC and Europe/Helsinki) and build;
  Worker changes also pass `npm run worker:check`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The owner does npm 2FA; outward steps (push, tag, publish) follow the owner's go-ahead.
- Stop after each task for the owner's check.

## Review Focus

- A closed Yolo page (menu section, no dated headings) asked for today: `no_menu/not_published_yet`,
  recorded by the collector as `none_listed`, no failure. → Task 1.
- Poweresta's menu list legitimately empty between seasons: still "nothing published", never an
  error. → Task 1.
- A stats.json written by the 0.3.1 collector (current real data shape) still decodes after the
  stricter validation. → Task 2.
- The rate-limit binding failing on every request: requests are still served and the instance
  limit still applies. → Task 3.
- `smoke:remote` against the right version whose `get_menu` fails: still a failure. → Task 3.
