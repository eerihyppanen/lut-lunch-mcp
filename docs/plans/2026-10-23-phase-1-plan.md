# LUT Lunch MCP — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stdio MCP server, published as `@eerihyppanen/lut-lunch-mcp`, with three tools (`get_menu`, `find_dishes`, `list_restaurants`) answering lunch questions for LUT Skinnarila campus restaurants.

**Architecture:** A runtime-agnostic `src/core/` fetches and parses three upstream sources (Poweresta JSON, Compass JSON, Aalef HTML), normalizes diets and allergens, caches whole weeks and resolves a status for every restaurant and date. `src/mcp/` registers tools on an `McpServer` built by `createServer(service)`. `src/bin/stdio.ts` wires the live service to a stdio transport.

**Tech Stack:** Node ≥ 22, TypeScript 6.0, `@modelcontextprotocol/sdk` 1.32, zod 4, cheerio 1.2 (slim), Vitest 5, ESLint 10 + typescript-eslint, Prettier, GitHub Actions.

**Spec:** `docs/specs/2026-10-23-phase-1-design.md`. Section references below (§n) point there.

## Global Constraints

- Runtime `engines.node`: `">=22"`. Development needs Node ≥ 22.13 (ESLint 10); `.nvmrc` contains `24`.
- `typescript` pinned to `~6.0.3`. typescript-eslint 8.72 supports TypeScript `<6.1.0`; TypeScript 7 is not supported yet.
- `"type": "module"`, `module`/`moduleResolution` `NodeNext`, `strict: true`, relative imports end in `.js`.
- Dependencies: `@modelcontextprotocol/sdk@^1.32.1`, `zod@^4`, `cheerio@^1.2.0`. Nothing else at runtime.
- cheerio is imported only as `cheerio/slim`.
- `src/core/**` must not import `node:*` modules or `@modelcontextprotocol/sdk`.
- Nothing writes to stdout except the MCP transport. All logging uses `console.error`.
- Every upstream request sends `User-Agent: lut-lunch-mcp/<version> (+https://github.com/eerihyppanen/lut-lunch-mcp)` and has an 8000 ms timeout.
- Restaurant ids: `lut-buffet`, `bistro-skinnarila`, `yolo`. Tool names: `get_menu`, `find_dishes`, `list_restaurants`.
- All dates are `YYYY-MM-DD` strings in Europe/Helsinki. Tests run with `TZ=UTC`.
- Tool output uses snake_case field names (§8); core types use camelCase (§5).
- Tool descriptions are the exact text in §8.1–§8.3.
- Deviation from spec §4: build with plain `tsc` instead of tsup. There's no bundling need, and it means one less tool. `tsc` preserves the `#!/usr/bin/env node` line.
- Refinement of spec §7.2 step 3: a date the source does not cover gets `history_not_available` if it is before today and `not_published_yet` otherwise. Yolo only lists today onward, so this case is real.
- Refinement of spec §5: core `Dish.allergens` gains `assessed: Allergen[]`, the allergens the source makes a statement about. `coverage` is derived from it. See Task 3.

## Review Focus

1. **The model passes a date in an unexpected form** (`"Friday"`, `"2026-10-23T10:00"`, `"next monday"`, `"2026-02-31"`). Expected: a tool error naming the accepted forms. Test added to Task 10.
2. **A dish is labelled gluten-free but its allergen list says "Cereals containing gluten"** (fixture: LUT Buffet "Nyhtökaura-perunavuoka", gluten-free oats). Expected: `exclude_allergens: ["gluten"]` keeps it (label wins, §6.2) and `contains` still lists `gluten`. Test added to Task 9.
3. **A restaurant id typed in another form** (`"Yolo"`, `"bistro"`). Expected: a validation error listing the valid ids. Test added to Task 10.
4. **One source fails while others work.** Expected: a full response with that restaurant as `error` and the others `open`. Test added to Task 8.
5. **A diacritic or case mismatch in search** (`"Itamaista"` vs "Itämaista", `"LOHI"`). Expected: it matches. Test added to Task 11.

Also added beyond the spec: a Poweresta dish name ending in an uppercase word (`"Kana BBQ"`) must not lose that word as a "code". Test in Task 3.

**Interfaces:**
- Produces (`dates.ts`):

  - `addDays(date: string, n: number): string`

### Task 3: Normalization — codes, diet tags, allergens, search text

**Files:**
- Create: `src/core/normalize/codes.ts`, `diets.ts`, `allergens.ts`, `text.ts`
- Test: `test/core/normalize/*.test.ts`

**Interfaces:**
- Consumes: types from Task 1.
- Produces:
  - `type SourceId = 'poweresta' | 'compass' | 'aalef'`
  - `parseCodes(raw: string): string[]`: split on commas and whitespace; a trailing `+` or `*` glued to a code becomes its own code; drop empties; keep order; dedupe.
  - `splitTrailingCodes(name: string): { name: string; codes: string[] }`: for Poweresta names. Take the longest trailing run of tokens separated by commas/whitespace in which every token (after `parseCodes`) is a known Poweresta code. Remove it and return its codes. If there's no such run, the name is unchanged.
  - `dietTags(source: SourceId, codes: string[], courseName: { fi: string; en: string | null }): DietTag[]`: mapping and implication rules from §6.1. The result is sorted in `DIET_TAGS` order. Unknown codes go to `warnOnce`.
  - `warnOnce(key: string, message: string): void` (module-level `Set`, `console.error`)
  - `powerestaAllergens(englishList: string[] | undefined): DishAllergens`
  - `aalefAllergens(codes: string[]): DishAllergens`
  - `compassAllergens(): DishAllergens`
  - `foldText(s: string): string`: lowercase, NFD, strip combining marks, collapse whitespace.

Known codes per source (anything else is "unknown"):
- poweresta: `G L M VL VE VG *`
- compass: `G L M VL Veg * A ILM VS`
- aalef: `G L M VL V + SE SO MU SI PÄ`

Vegetarian course regex: `/kasvis|vege|vegetarian/i` on `fi` or `en`.

Poweresta allergen names (case-insensitive; a `May contain: ` prefix goes to `mayContain`):

| Source name(s) | Allergen |
|---|---|
| Cereals containing gluten, Wheat, Rye, Barley, Oat, Oats, Spelt | gluten |
| Milk | milk |
| Eggs, Egg | egg |
| Fish | fish |
| Crustaceans | crustaceans |
| Molluscs | molluscs |
| Peanuts, Peanut | peanuts |
| Nuts, Tree nuts | nuts |
| Soybens, Soybeans, Soy, Soya | soy |
| Celery | celery |
| Mustard | mustard |
| Sesame, Sesame seeds | sesame |
| Sulfur dioxide and sulfits, Sulphur dioxide and sulphites, Sulphites | sulphites |
| Lupin | lupin |

Coriander, Peas, Pulses and other names are ignored silently (not in the EU-14 list). An item can't be both: `contains` wins over `mayContain`.

Coverage rules:
- `powerestaAllergens(list)`: `assessed = ALLERGENS` when the list is defined, `[]` when undefined.
- `aalefAllergens`: `assessed = ['egg', 'soy', 'celery', 'mustard', 'nuts']`, `contains` from `MU SO SE SI PÄ`.
- `compassAllergens`: `assessed = []`.
- `coverage`: `full` when `assessed` has all 14, `partial` when it has some, `none` when empty.

  - `createFetchHttpClient(opts: { userAgent: string; timeoutMs?: number; fetchFn?: typeof fetch }): HttpClient` (default timeout 8000)
  - `USER_AGENT` built from `VERSION`
- Produces (`cache.ts`):
  - `interface CacheStore { get(key: string): CacheEntry | undefined; set(key: string, entry: CacheEntry): void }`
  - `type CacheEntry = { ok: true; value: unknown; fetchedAt: number } | { ok: false; error: SourceError; fetchedAt: number }`
  - `class MemoryCacheStore implements CacheStore`
  - `class CachedLoader { constructor(store: CacheStore, now: () => number); load<T>(key: string, freshMs: number, fn: () => Promise<T>): Promise<{ value: T; stale: boolean; fetchedAt: number }> }`
  - Constants: `STALE_LIMIT_MS = 24 * 3600_000`, `NEGATIVE_TTL_MS = 60_000`

`load` behaviour, in order:
1. A fresh ok entry is returned (`stale: false`).
2. An identical key already in flight shares that promise.
3. A failure entry younger than `NEGATIVE_TTL_MS` with no ok fallback rethrows its error without calling `fn`.
4. Otherwise `fn` is called. On success, store and return it. On failure: if an ok entry younger than `STALE_LIMIT_MS` exists, return it with `stale: true` and keep it stored (don't overwrite it with the failure); otherwise store the failure and throw.
5. Errors that aren't `SourceError` are wrapped as `SourceError(message, false)`.

`createFetchHttpClient` error classification:
- `retryable: true`: timeouts (`AbortSignal.timeout`), network errors, HTTP 5xx and 429
- `retryable: false`: other 4xx, invalid JSON

Every request sets the `User-Agent` header.

  - `type FilterVerdict = 'keep' | 'hidden' | 'unverifiable'`
  - `judgeDish(dish: Dish, filter: DishFilter): FilterVerdict`
  - `allergenVerdict(dish: Dish, allergen: Allergen): 'ok' | 'excluded' | 'unverifiable'`
  - `hasFilters(filter: DishFilter): boolean` (diet or allergens; query alone doesn't count)
- Produces (`present.ts`):
  - `presentDish(dish: Dish, lang: Language): DishOut`, where `DishOut = { name: string; untranslated: boolean; tags: DietTag[]; codes: string[]; allergens: { coverage; contains; may_contain } }`
  - `presentRestaurantDay(day: RestaurantDay, lang: Language, filter: DishFilter): RestaurantDayOut`. Fields per §8.1. `reason` is `'source_unavailable'` for errors. `hidden_by_filters` counts `hidden` dishes, `unverifiable` counts `unverifiable` dishes, and courses left empty are dropped. `source_url` comes from the registry `menuUrl`.
  - `type Language = 'en' | 'fi'` (exported from `schemas.ts`)
  - `NOTICE`: the exact text from §6.4
- Produces (`schemas.ts`): zod schemas `DateInput`, `RestaurantIdsInput`, `DietInput`, `AllergenInput`, `LanguageInput`, `DishOutSchema`, `RestaurantDayOutSchema`, reused by both tools.
- Produces (`format.ts`):
  - `formatDays(out: GetMenuOutput): string`
  - `formatMatches(out: FindDishesOutput): string`
  - Tag abbreviations in text: vegan `vegan`, vegetarian `veg`, gluten_free `GF`, milk_free `MF`, lactose_free `LF`, low_lactose `LL`. Implied tags are omitted (a vegan dish shows `vegan, GF` rather than six tags).

`allergenVerdict` (§6.2):
- `gluten` → `ok` if tagged `gluten_free`, else `excluded`
- `milk` → `ok` if tagged `milk_free`, else `excluded`
- other allergens → `excluded` if in `contains`/`mayContain`; `ok` if in `assessed`; else `unverifiable`

`judgeDish`:
- `hidden` if a diet tag is missing, the query doesn't match the folded fi+en name, or any allergen is `excluded`
- `unverifiable` if any allergen is `unverifiable` and none are `excluded`
- else `keep`

Language: `en` uses `name.en ?? name.fi` with `untranslated: name.en === null`; `fi` uses `name.fi` with `untranslated: false`.
